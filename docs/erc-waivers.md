# ERC Waivers

Tracks intentionally-accepted ERC warnings (with justification), sheet by sheet,
as the hierarchy is populated. Task 3 baseline was 0 errors / 0 warnings on an
empty scaffold. Task 4 (power_input) is the first sheet with real content;
`$KCLI sch erc sierra-to-usb.kicad_sch` now reports **0 errors / 159
warnings**, all four categories below, all on this sheet.

| Date | Warning | Justification |
| ---- | ------- | -------------- |
| 2026-07-14 | `isolated_pin_label` ×4 — global labels `POE_VA+`, `POE_VA-`, `POE_VB+`, `POE_VB-` each connect to only one pin (BR1/BR2's AC-input pins) | Expected and documented in the Task 4 brief: these hierarchical/global labels are the sheet's *export* of the PoE center-tap signals — the matching consumer (J4 magjack on `sheets/ethernet.kicad_sch`) is wired in Task 10. Until then a single-pin global label is correct, not a wiring defect. Re-check after Task 10 that the warning clears. |
| 2026-07-14 | `power_pin_not_driven` (pre-fix, now silenced by design) — `U2` pin 1 (VDD, fed via `R_VDD` from `VBUS_PD`) and `U10` pin 42 (VCC, fed via the bias-winding rectifier `L9`/`D16`/`C32`) | Not a live warning (both are ERC **errors**, fixed by adding `PF_CH224K_VDD` / `PF_U10_VCC` `PWR_FLAG`s on the two derived rails) — logged here for traceability since ERC's simple pin-type model can't see "power delivered through a passive network" and needs an explicit assertion. |
| 2026-07-14 | `footprint_link_issues` ×50 — every placed symbol's `Footprint` field points at a library (`Diode_SMB`, `R_0603`, `Package_DFN_QFN`, `Transformer_SMT_XFRMR_29MM08_23MM1`, etc.) not yet present in `fp-lib-table` | Footprint/library binding is explicitly a Task 14 activity per the plan (`docs/sourcing.md` already flags several packages — e.g. CH224K's ESSOP-10, TS3A27518E TSSOP-24/WQFN-24 — as "verify footprint at Task 14"). The `Footprint` string on each symbol here already records the *intended* package (matching `docs/sourcing.md`/datasheet packages) so Task 14 has the real target, not a placeholder; only the fp-lib-table registration is deferred. |
| 2026-07-14 | `lib_symbol_mismatch` ×3 — `SMAJ13A`, `SMAJ58A` (base `SM6T6V8A`), `TCMT1107` (base `TCMT1100`) cached copies in this sheet's `lib_symbols` differ from the stock library on disk | These three stock symbols use KiCad's `extends` inheritance. To keep the schematic file self-contained (so `kicad-cli` doesn't need to re-resolve `extends` against the system library at parse time), Task 4's generator flattens each into a standalone symbol (own name, base's graphics/pins merged in). The flattened copy is electrically identical to the real symbol — same pin numbers/positions/types — but differs structurally (no `extends` link), which is exactly what this checker flags. Cosmetic only; verified pin-for-pin against the real `Diode:SMAJ13A`/`Diode:SMAJ58A`/`Isolator:TCMT1107` definitions before flattening. |
| 2026-07-14 | `endpoint_off_grid` ×102 — pin/label/power-symbol endpoints not on KiCad's default 50/100 mil edit grid | This sheet was authored by a script that places every label/power-symbol anchor at the *exact* absolute coordinate of the pin it connects to (computed from each symbol's real datasheet-derived pin table), rather than snapping to the editor's visual grid. Electrically correct (verified via `check_nets.py` and direct netlist inspection) but cosmetically off-grid; a GUI cleanup pass (Move/re-snap) would silence this without changing connectivity, and is not required for the ERC error gate. |
