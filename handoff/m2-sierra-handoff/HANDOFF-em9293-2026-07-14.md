# EM9293 M.2 Carrier — Session Handoff (2026-07-14)

Background + current state for continuing the **Sierra/Semtech EM9293 5G M.2 carrier board** in a fresh session. Read this first, then the source-of-truth docs listed in §8.

---

## 1. What this project is

A custom **M.2 Key-B carrier board** that runs a **Sierra Wireless EM9293** 5G modem in **forced-USB SuperSpeed** mode, for bench bring-up and throughput testing against the user's existing RM551E setup. Designed originally in **EasyEDA Pro** for **JLCPCB PCBA** (all LCSC parts). **As of 2026-07-14 the project is being migrated to KiCad 10** (schematic already imported; see §7).

The user is not selling this board — "we can go overkill" on robustness.

## 2. Goal & hard constraints

- **Forced-USB bring-up of the EM9293** (it defaults to PCIe). Per the *EM92XX Product Technical Specification Rev 1, Doc# 41114313* (Table 3-1, §3.2–3.10):
  - **Pin 6** `Full_Card_Power_Off_N` pulled **high** (R9 100k → +3V3).
  - **Pin 20** `PCIE_DIS` → **1.8 V**.
  - **Pin 22** `VBUS_SENSE` driven **high** (from the data-port VBUS via R12 33 Ω) — required for USB activation.
- **USB 3.x SuperSpeed** data path to a host PC (board is a **UFP/device** toward the PC).
- **Dual SIM** (UIM1 external 1.8/3 V + UIM2 1.8 V-only).
- All parts **LCSC / JLC-orderable**.

## 3. Architecture (from the 07-14 netlist)

| Ref | Part | Role |
|---|---|---|
| CN1 | M.2 Key-B socket | the EM9293 module |
| USB1 | USB-C receptacle | **data** port (SS + CC + USB2 + VBUS_DATA) |
| USB2 | USB-C receptacle | **power/PD** port (VBUS_PD + CC only) |
| U1 | **HD3SS3220** | Type-C CC logic **+** 2:1 SS orientation mux (standalone UFP: presents Rd, detects orientation, steers mux) |
| U2 | **CH224K** | USB-PD sink on the power port |
| U3 | **TPS565201** | sync buck, VBUS_PD → main rail |
| U4 | LDO | makes the mux's local 3V3 (`$1N75`) from VBUS_DATA (mux alive whenever data cable present) |
| U5 | **AP2112K** | LDO(s) for +1V8 / +3V3 |
| SIM1/SIM2 | dual nano-SIM | UIM1 + UIM2 |
| D1/D4 | TPD4EUSB30 | connector-side SS ESD (flow-through) |
| D6 | TPD4EUSB30 | module-side SS ESD |
| D2 | TPD4E05U06 | CC + USB2 D± ESD (data port) |
| D3/D5 | SMAJ TVS | VBUS_DATA / VBUS_PD clamps |
| C14/C15 | AC caps | USB3 RX coupling — **currently on the WRONG pair, see §5** |
| R15/R16 | 0 Ω 0402 | USB2 D+/D- A↔B crossover jumpers — **currently inert, see §5** |

Two separate USB-C ports by design: **data** (USB1 → HD3SS3220 → module) and **power/PD** (USB2 → CH224K → buck). VBUS_DATA is used only for mux power + the module's VBUS_SENSE; VBUS_PD is the real power input.

## 5. Verified issues to fix (prioritized) — from the 07-14 netlist/DXF review

**🔴 1. AC-coupling caps on the WRONG SuperSpeed pair (electrical bug).**
`C14/C15` sit between the mux RX (U1.6/7) and **M.2 pins 35/37** = the **module-TX / host-RX** link (`USB3_RX` net). The **module-RX / host-TX** link (mux U1.9/10 → **M.2 29/31**, `USB3_TX` net) has **no caps**. Per EM92xx PTS §3.3.1 ("series caps on the host side for the module's RX; none on the module's TX"), it's backwards.
→ **Fix:** move C14/C15 onto the `USB3_TX` pair (M.2 29/31); remove them from `USB3_RX` (let 35/37 run straight through the ESD — the module caps its own TX). **Re-confirm which M.2 pins the PTS calls the module's RX before committing** — the whole fix hinges on that (cross-checked to M.2 Key-B standard: 29/31 = module Rx, 35/37 = module Tx).

**🔴 2. Board is 2-layer — no controlled 90 Ω on the SS pairs.** DXF shows only Top/Bottom copper, bottom is not a solid plane, ~0.20 mm traces. USB3 needs a continuous ground reference.
→ **Fix:** go **4-layer** (Sig / GND / PWR / Sig). The original spec (see specs doc) already called for 4-layer; the layout regressed to 2. This is the #1 thing for reliable 5 Gb/s.

**🟠 3. No impedance / length rules.** `netClass`, `equalLengthNetGroup`, and every net's `TrackPhysics` are empty. Diff pairs are associated (P/N) but have no 90 Ω target, width/gap, or skew match.
→ **Fix:** set a 90 Ω differential net class on the SS pairs **and** the USB2 pair only; CC/everything else stays default.

**🟠 4. USB2 crossover jumpers R15/R16 are inert.** Both pads of R15 are on `USB2_DP`, both of R16 on `USB2_DM`, and A6+B6 are already tied — so the router treats them as redundant shorts and won't force the D± bridge.
→ **Fix:** split nets (A6→`DP_A`, B6→`DP_B`, R15 bridges them; same for R16 on D−), **or** delete R15/R16 and do the crossover with a symmetric via. (See the D+/D− crossover reference in this bundle.)

**🟡 5. PD-port CC has no ESD.** `USB2_CC1/CC2` go straight to the CH224K with no ESD array (the data port has D2). Add a small CC ESD for parity.

**🟡 6. Confirm the 65-pin no-net group is intentional NC** (M.2 reserved pins, SBU A8/B8, SIM CD, mux/CH224K NC pins). Add **No-Connect flags** for clean ERC; verify none are signals that should be routed (esp. mux U1.11/22–27, CH224K U2.2–5).

**🟡 7. Board outline reads 200×100 mm** in the DXF — almost certainly the sheet frame, not the board. Confirm real dimensions.

## 6. What's CONFIRMED CORRECT (don't "re-fix")

- **All connector-side SS pair polarity** (SSTX1/2, SSRX1/2 map per USB-C standard).
- **M.2 SS polarity + TX/RX crossover**: host TX → module RX (pins 29/31); module TX → host RX (pins 35/37). Directions and ± all correct.
- **Polarity preserved** through the mux and the AC caps (no P/N flips).
- **ESD flow-through** on every SS pair (D1/D4 connector-side, D6 module-side; connector-side SS ESD was added to protect the mux's 2.5 V-abs-max SS pins).
- **USB2 D+/D- kept correct polarity** to the module (NOT swapped — USB2 is polarity-sensitive; only SS pairs may be inverted, and they self-correct at link training).
- **CC1/CC2 need no controlled impedance** (single-ended, low-speed: DC + ~300 kHz BMC PD). Route loose; keep off the buck SW node; don't add >~600 pF.
